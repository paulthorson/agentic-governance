## Admin twin (definition)

The local `/admin` already in place — same look and craft as the public living board,
sensitive numbers and ops controls behind that door; one product, two doors (public
board vs local admin), not a cheap separate back office.

---

## Box 1 — Business problem

Teams ship AI work without a visible governed loop — operators, buyers, and design
leads cannot see whether diligence and craft are real week to week, so AG reads as a
pitch instead of a product people trust enough to run.

## Box 2 — Business outcomes

- Weekly governed loop in use
- Fewer rework cycles
- More serious evals

## Box 3 — Users

- Alex — operator-founder
- Jordan — enterprise buyer
- Sam — design lead

## Box 4 — User outcomes and benefits

- Alex — trust that the loop is real (diligence visible on a living board)
- Jordan — diligence he can take seriously (one product, not a pitch + cheap back office)
- Sam — craft challenged before Eng (same board + download path)

## Box 5 — Solutions

- Living board
- Get AG
- Narratives (plain-English stories of what shipped)
- Admin twin (all of the above as one product, two doors)

## Box 6 — Hypotheses

1. We believe operators will run a weekly governed loop (and cut rework) if Alex can see
   real ships update a living board and read plain-English stories of what shipped.
2. We believe more serious evals happen if Sam’s craft gets challenged before Eng, via
   the same board + download path.
3. We believe Jordan takes AG seriously if the public board and the private local admin
   twin look like one product — not a pitch page with a cheap back office.

## Box 7 — Most important thing to learn first

Does a living board with plain stories actually make operators run the weekly loop?

## Box 8 — Least amount of work to learn that

Interview 5 operator-founders with stills + sample stories; ask if they’d run a weekly
loop.
