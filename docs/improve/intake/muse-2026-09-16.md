**E2E retro-validation program (the human's standing gate, applied retroactively)**

- The human ordered every shipped feature retro-validated with end-to-end tests against real surfaces. Eight already-shipped initiatives each got a new E2E file driving the real CLI / real entrypoints / real on-disk state (96 new tests), each reviewed blind before commit. Nothing was weakened to make tests pass: when tests asserted pre-hardening behavior, the tests were moved up to the product, never the other way.
- Every approval gate deserves its negative case in e2e, not just in unit tests. The most valuable tests in the program were the ones that made the gates FAIL on purpose: an unreviewed packet refused with a blocked exit code; a privacy validator fired on undeclared fragments; a corrupted consent store made every entry point refuse. A gate tested only on passing cases is a hope, not a control.
- When a production security gate refuses non-interactive callers, tests must simulate the human at the gate and put the real gate back afterward — never weaken the gate, never thread a bypass through production. The gate's own refusal semantics (refuse without a terminal, decline means refusal) belong in a separate dedicated test file, not folded into the simulated tests.
- When an e2e test finds a "hole," check the product's identity conventions before calling it a bug. A test run under an identity the product never runs with tests a fiction; the product's single-user identity convention was load-bearing for blocks, discovery exclusions, and consent handshakes.
- Test-environment accommodations go in the test, never in the product: a sandbox that fails the real 500 MB disk check got a lowered threshold inside the test only (production minimum unchanged); tools that write their own audit files into the target were excluded from byte-fidelity comparisons rather than the comparison being weakened.
- Process-global environment overrides at test-module import time are a trap in a big suite: one file's import-time override poisoned another module's tests when collected together. Prefer per-test seams, even when the global looks easier — the modules in question already documented the seams; reading first would have saved the hack.
- False-positive-prone assertions are worse than no assertions. A blunt "no submit-related word anywhere in the artifact" check would have flagged honest product text (e.g. resume copy) forever. Legal-boundary tests must use precise symbols, and the retro should record which blunt checks were rejected and why.
- Sanity controls prove the refusal came from the right check: rollback succeeding when nothing is revoked is what makes rollback-refusing-when-revoked meaningful, rather than a broken store.

**Live-surface checks (marketing site)**

- Live-site tests must fail with evidence, never skip. An egress outage during the session proved the policy the same day: a skip would have hidden the outage, a fail records it. Network-dependent tests that skip on failure are a silence machine.
- The repo's local stale build must never be used as the expected-build source; expected production markers (canonical URL, hashed bundle asset, no stale claims) come from the deployment record and the live site itself. One KICK_BACK caught a review bundle that falsely claimed "all local flows run the real CLI with nothing mocked" while one test ran in-process behind a mock — the honest carve-out (no env var/flag for the state-file location, so no subprocess redirect without touching product code) was stronger than the false claim.

**Framework-sync incident: import-time side effects**

- A framework sync changed framework import-time behavior, not just APIs: a framework setup module inserts its own directory at the front of `sys.path` at import time, permanently shadowing the consumer repo's same-named module for the rest of the process. Framework code is off-limits to consumer edits, so the fix is consumer-side: the adapter now snapshots the module search path before import and scrubs framework-root entries afterward (pre-existing caller entries preserved).
- Transferable: treat framework import boundaries as untrusted code with side effects (search path, environment, working directory). The scrub is now the containment point for future framework edits. Engine feedback for the framework's own loop: import-time side effects in shipped framework modules deserve adversarial review at the framework level, not discovery by consumers.

**Automated UAT as a standing ship gate**

- The human made user acceptance testing a standing ship gate alongside E2E and blind review. Seven automated acceptance journeys (42 checks, all green) now produce a plain-English acceptance report the human signs to accept or reject each initiative; CI regenerates and uploads the report on every run, and the runner exits nonzero on any journey failure so a failing UAT can never upload a green-looking artifact.
- The report the human signs is itself a deliverable: it needed its own blind docs review, which caught real signability defects (two conflicting sign-off instruments, signature placed above the caveats, engineer jargon). "Automated UAT" is not done when the tests pass; it is done when a non-technical signer can read the report and decide.
- Never invent acceptance criteria. Where the roadmap had epics but no story criteria, the honest move was asserting the weaker checkable property and saying so. Three KICK_BACKs on overstated or invented criteria were reworked into the strongest parts of the report. A KICK_BACK on invented criteria is the loop working, not failing.
- Environment note: the repo-tree tripwire fails closed on concurrent edits — overlapping full-suite runs from two agent sessions trip each other's tripwires, and the file lock serializes runs, not edits. Final evidence runs need a quiet tree.

**Tree hygiene**

- Uncommitted program output sat in the tree for about a day after the E2E program's close-out; the nightly loop committed it per workstream. Streams should commit same-day — committed work is visible progress, uncommitted reviewed code is invisible progress.
