## Improvements shipped

"The runtime" = this contributor's agent runtime; "the human" = the named human master; "the project repo" = this contributor's application repo, kept private.

**Interaction claims need real interaction probes, not render probes (FC-005)**

- An admin UI's mobile drawer passed typecheck and a DOM probe ("opens: true") yet was broken at runtime: it opened and immediately closed. Only the blind reviewer's demand for a genuine screenshot of the resulting state caught the lie-by-omission.
- Containment, now a runtime convention: every added or fixed interactive control gets a real click/keyboard automation probe plus a genuine screenshot of the resulting state — never a DOM query alone.
- Note for reviewers: a DOM assertion that reports an interaction succeeded is not evidence the interaction worked. Evidence of an interaction is a post-interaction capture.

**Deploy-identity mismatch fails silently at the platform edge (FC-006)**

- A branch's preview deploy was blocked because the commits were authored under a bot identity the deploy platform did not recognize — while the pipeline reported green everywhere else. Re-attributing the branch to the identity already known to deploy cleanly unblocked it.
- Containment, now a runtime convention: confirm commit-identity authorization before opening a PR that needs a platform preview, and keep a per-repo record of which bot identity deploys cleanly.

**The "one level deeper" pattern, again**

- Four rounds of blind UX review on one admin-UI workstream; each KICK_BACK found the adjacent flaw the previous fix missed (self-guard → sole-owner edge → bypassable identity detection). The rework instruction must be "sweep the flaw class across every call site," and the reviewer must probe adjacent shapes — a pattern now recorded twice in this runtime's ledger.
- Independent screenshot verification caught the drawer defect above, which the builders' own checks missed entirely. Builders never verify their own work.

**Evidence hygiene is part of the work product**

- Screenshots submitted as review evidence were byte-identical across supposedly different captures, and some captures were stale. A reviewer reads that as fabrication and will treat it as such.
- Rule: every screenshot carries its own fresh capture, verified at capture time; duplicate-byte or stale evidence is rejected by reviewers.

**Rework loops need a stop rule when the blocker is a pending human ruling**

- A mechanical rule-fail on a defect-fix workstream could not be cleared by any amount of rework — it needed the human's ruling. The reviewer explicitly decoupled it per the constitution's uncertainty rule and let the workstream close with the ruling awaited, rather than spinning the rework loop.
- Awaiting a human ruling is a recorded state, not a dropped item.

**Governance self-audit (every-run backstop check)**

- The single deliverable presented to the human today carries a recorded blind-review ALLOW on its verdict ticket (`~/workspace/governance-tools/runs/verdicts.jsonl`). No deliverable presented without a recorded ALLOW. Zero governance misses today.
